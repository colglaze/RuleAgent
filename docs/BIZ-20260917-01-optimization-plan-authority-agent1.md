## 已裁决的来源冲突

1. **线下释放 / 批量释放编码**：本版本以优化方案物理码为准，命中码为 `0`。不再把工作簿 `4/5` 作为本版本规则值域。由此消除 `SOURCE_CODING_DIVERGENCE`，而不是删除 warning。
2. **报告有无**：`0` = 有，`1` = 无。任一为有即通过，包括一有一空；双无为无需释放；其余（含未知码、字段缺失）等待满足条件。覆盖 3×3 矩阵。
3. **R0 空值**：金额等于 0 命中；NULL 不命中 R0，继续后续判定，且不绕过共同前提或后置约束。
4. **R5/R6 适用范围**：§1.3 规则名明确“非框架 + 企业/非企业”，§5.2 Java 未写 `isFramework` 检查。本版本按规则名补齐非框架前置，避免框架订单误入 R5/R6 而使 R7 不可达。金额公式仍严格取自 §5.2（含比较式中的 `+ 0.1`）。
5. **R4 释放标志**：§5.2 Java 使用与“有无原始数据”相同的任务标志编码 `0`。本版本按用户要求拆成“已释放状态 + 完工日 ≥ 截止日参数”，使用数据释放状态 `已释放`，避免与原始数据规则集的有无标志混用。
6. **R8 上线日**：§5.2 注释写明 2026-04-15 上线，示例 `match()` 未判断该日。本版本把上线日作为整个 R8 的运行参数前置。
7. **§5.2 比较容差 `+ 0.1`**：属于优化方案示例本身的数值，不是从现行视图另引入的第二套容差；在 R3/R5/R6/R7/D4 到款比较中按原文保留。

## 阶段语义

- `stateGuards` / `prerequisites` / `postGates` / `exclusions`：命中即终止。
- `eligibility`：按给定顺序取首个命中，然后继续后置阶段；不得在初步 READY 时直接结束。
- 默认结果：`WAITING_CONDITIONS`。
- 未知值：按节点 `nullPolicy` 传播；eligibility 若存在未决比较且无命中，结果为 `INDETERMINATE`。

## 合并组

- 仅项目报告规则集。成员集合可查询；全员满足才放行。
- 空组（无其他成员）视为满足；集合缺失/未知不得判为全员满足。
- 重复成员按唯一键去重后求值。
- 成员已达准备释放/释放中/已释放视为满足；否则用精简前提（已完工且有报告）+ eligibility 任一命中，**不含**合并组与 OA，避免循环。
- 空组口径来自 §5.2：相关成员查询结果为空则全部满足。
