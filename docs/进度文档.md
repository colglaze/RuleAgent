## 当前状态

Phase 0 文档基线、Phase 1.0 后端骨架和 Phase 1.1-1.5 规则解析闭环均已完成。项目运行时锁定为 Python `3.11.9`，依赖管理采用 `venv + pip + pyproject.toml`，Agent 编排框架为 LangGraph，模型供应商为 DeepSeek。

后端现已具备 FastAPI/Uvicorn 服务、集中配置、脱敏配置检查、PyMongo Async 生命周期、MongoDB Schema v2 幂等迁移、健康检查和自动化测试。Rule Parsing Agent 已实现 camelCase JSON 契约、确定性语义校验、四视图字段目录、LangGraph 有限重试图、DeepSeek JSON Output 适配器、受控 Markdown 读取、HTTP 文本入口和 CLI 文件入口；规则版本仓储支持显式不可变保存与精确版本回读。

Phase 1.6 已按用户授权完成：增加显式、不可变的 MongoDB 草稿版本归档，并保存一版《项目报告释放规则》。规则仍固定为待人工审核的 `draft` 且不可执行。

2026-08-19 完成了已归档 JSON 向 Agent 2 交接的只读兼容性评审。评审确认 JSON 的版本、来源、Schema 和候选映射结构便于程序读取，但归档条件树存在公式和分支语义丢失，且现有校验未能阻止；已记录为 [BUG-20260819-01](BUG-20260819-01-rule-ast-semantic-loss.md)。该草稿不得作为 Agent 2、规则执行或发布输入。

用户确认双服务事实级交接基线后，Phase 1.7 已完成：应用版本升级为 `0.4.0`，新解析固定生成 Schema `2.0.0`；结构化表达式、事实种类/粒度/参数/派生、严格引用闭包、类型校验和确定性案例执行已落地；历史 Schema `1.0.0` 保持只读兼容。新增按精确规则版本导出非派生 `FactBindingRequest[]` 的 HTTP 入口，RuleReader 内仍不实现 SQL、目标库元数据或 Agent 2 模型调用。
