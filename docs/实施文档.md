### Post-Phase 1.10：DeepSeek 重试、审计与幂等性治理

状态：`COMPLETED`（2026-08-27）

- 应用升级到 `0.10.0`，MongoDB Schema 保持 v3，规则 Schema 保持 `2.0.0`；
- 可重试 Provider/候选失败在下一次调用前执行确定性、有上限的指数退避，总尝试数继续为 `max_retries + 1`；
- Provider 适配器提取并校验 completion ID 和可用 token usage，LangGraph 在成功与最终错误中输出逐次及汇总审计；
- HTTP `Idempotency-Key` 和 CLI `--idempotency-key` 进入同一进程内协调器，同键同身份合并在途调用并重放成功结果，同键异身份 fail closed；

DoD：退避边界、尝试次数、逐次 outcome、Provider ID/token 汇总、顺序/并发重放、冲突、失败后重试和 LRU 淘汰均有确定性测试；reviewed import 的旧 JSON 形状不变；默认测试不调用 DeepSeek、网络或 MongoDB；Ruff、严格 Mypy 和依赖检查通过。详细标准见 [REQ-20260827-02](REQ-20260827-02-deepseek-retry-audit-idempotency.md)，完成证据见 [PROG-20260827](PROG-20260827.md)。
