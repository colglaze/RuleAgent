# BIZ-20260818-01：第一阶段使用本地文档

- 状态：`ACCEPTED`
- 日期：2026-08-18
- 来源 REQ：[REQ-20260818-01](REQ-20260818-01-vibe-coding-bootstrap.md)
- 影响范围：第一阶段实施顺序与规则来源

## 1. 决策

1. 根目录总体方案继续作为长期目标架构。
2. 第一阶段只实现 Rule Parsing Agent，不实现总体方案中的其他 Agent 或运行时链路。
3. 第一阶段规则来源采用受控目录中的本地 Markdown 文档，不接入 Wiki。
4. 解析产物只作为待人工审核的规则草稿，不发布、不执行，也不改变正式业务状态。
5. Wiki、Agent 2、SQL、事实注册、规则执行、诊断和销售查询能力推迟到后续 REQ；当前阶段不创建占位代码或预留型基础设施。

## 2. 原因

- 先验证“自然语言规则能否稳定转换为受约束的结构化规则”这一项核心风险。
- 本地 Markdown 能减少外部系统权限、同步、版本和网络故障带来的变量。
- 缩小纵向切片，便于为 Schema、语义校验和失败路径建立可重复测试。
- 避免因长期方案完整而误把全部模块并行开工。

## 3. 影响

- 当前实现不得依赖 Wiki SDK、Wiki 凭据、RAG 或向量数据库。
- 本地文档必须保留路径和内容哈希等来源信息，为人工复核提供依据。
- 后续接入 Wiki 时应通过新的 REQ/DEV 评估来源适配边界；本阶段不为该能力提前设计通用框架。
- `project_release_double_agent_solution.md` 的阶段计划已按本决策重新分段。

## 4. 退出条件

只有在 Rule Parsing Agent 的本地文档闭环达到第一阶段 DoD，且用户明确批准新的 REQ/BIZ 后，才能进入 Wiki 或其他长期模块。
