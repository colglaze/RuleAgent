### 7.2 实施内容

- 应用从 `0.9.0` 升级到 `0.10.0`；Python `3.11.9`、MongoDB Schema v3 和规则 Schema `2.0.0` 不变。
- 配置新增基础退避、最大退避和有界幂等缓存容量；第 2 次尝试起按指数退避并封顶。
- Provider 端口返回 provider-neutral `CandidateGeneration`；DeepSeek adapter 校验 completion ID，并提取标准 token usage、缓存 token 和 reasoning token 子项。
- LangGraph 对每次调用记录退避、稳定 outcome、retryable、Provider completion ID 和 usage；成功草稿写入 `parser.audit`，最终错误写入 `error.audit`，全部调用 usage 汇总包括被候选门禁拒绝的尝试。
- HTTP 接受 `Idempotency-Key`，CLI 接受 `--idempotency-key`；内部只保存 SHA-256 和请求 fingerprint。
- 同键同身份的顺序请求精确重放成功结果，并发请求共享一个在途 Provider task；同键异身份返回 409，无效键返回 422，失败不进入完成缓存，有界 LRU 超限淘汰最久未使用项。
- HTTP 成功和已有 parse audit 的错误返回 `X-RuleReader-Request-ID`；日志只记录稳定错误码和 RuleReader request ID。
- `ParserMetadata.audit=None` 使用字段级排除，reviewed import、历史 V1/V2 和事实交接 JSON 不新增 `audit: null`。
